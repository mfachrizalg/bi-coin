# Domain Docs

Use a single-context layout. Read root `CONTEXT.md` and relevant `docs/adr/` files when they exist. For Fabric work, also read the existing `bi-coin-fabric/CONTEXT.md` and relevant `bi-coin-fabric/docs/adr/` files.

If a domain doc is absent, continue without treating its absence as a setup task. Create domain docs later when `/domain-modeling` records a resolved term or decision.

Use glossary terms consistently in issues, tests, and proposals. If work conflicts with an ADR, identify the ADR and explain the conflict before proposing a change.
